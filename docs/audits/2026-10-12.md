# Site audit — October 12, 2026

Reviewed [justinmusick.com](https://justinmusick.com/) and source commit `24b29bf70b5e9f66c22cb84c8de8a08aa5f76c52` (v1.9.0). The portfolio's goal is to present Justin Musick's engineering experience and projects and support contact inquiries.

The site has sound metadata, canonical redirects, structured data, and static-response security headers. The highest-priority defect is clipped content at 320 CSS pixels, including contact controls. Contact announcements, endpoint hardening, development dependency updates, incorrect status codes, and page delivery also need attention. Ten GitHub issues were created with evidence, proposed fixes, and acceptance criteria.

## Measurements and checks

Lighthouse 13.5.0, Chromium 156, one navigation run per profile:

| Profile | Performance | Accessibility | Best practices | SEO | FCP | LCP | CLS |
|---|---:|---:|---:|---:|---:|---:|---:|
| Mobile | 63 | 100 | 92 | 100 | 3.7s | 15.5s | 0 |
| Desktop | 76 | 100 | 92 | 100 | 1.2s | 4.2s | 0 |

These are lab results, with simulated Lighthouse throttling, rather than field Core Web Vitals. INP was not measured. The mobile hero PNG is 1,149,864 bytes; Lighthouse estimates 887,735 bytes of image savings and 1,210ms of aggregate render-blocking savings. Repeated comparable runs should establish a baseline before evaluating fixes.

- Axe-core 4.14.0 reported zero violations on the desktop and 320px snapshots. That result does not establish WCAG conformance: manual checks found clipping and missing status announcements.
- Browser checks covered 320, 375, 640, and 1280px widths, first-tab skip-link visibility and destination, keyboard accordion activation, form feedback, and reduced-motion behavior. The 320px test represents the reflow width used for 400% zoom on a 1280px viewport; native browser zoom and a screen reader remain follow-up checks.
- HTTP and `www` redirect to the canonical HTTPS root with 301; `/index.html` redirects to `/` with 308. Canonical/title/description/social metadata, one h1, orderly project headings, and Person JSON-LD were inspected in the rendered DOM.
- Robots and sitemap return 200 and reference the canonical root. Unknown paths and GET `/api/contact` return homepage HTML with 200. A POST containing `{}` returns 400 JSON without sending email.
- Static HTML has enforced CSP, HSTS, nosniff, frame protection, referrer and permissions policies. Function-generated JSON has content type and no-store but lacks applicable hardening headers.
- The lockfile dependency audit reports 6 high, 1 moderate, and 1 low affected packages. The production-only audit reports zero advisories. Locked React/react-dom are 19.2.6 and Vite is 8.0.11; manifest minimums differ from installed/locked versions.
- Offline contact checks mocked all provider calls. They confirmed unrestricted test-result handling, acceptance of JSON under `text/plain`, parsing of a 1MB body before rejection limits, and an email fetch without a deadline. No live valid-token submission, mail delivery, oversized request, or flood was performed.
- Repository lint and production build passed. Changes from this pass are asset organization and documentation; remediation remains in the issues. No commit, push, or deployment was performed.

## Security scope and current guidance

As of October 12, 2026, [OWASP Top 10:2025](https://top10.owasp.org/2025/) and [ASVS 5.0](https://github.com/OWASP/ASVS) provide the review baseline. Relevant threats include exposed Vite development servers and abuse of public mail endpoints. Current [Vite support guidance](https://vite.dev/releases) calls for a supported patched release; the locked 8.0.11 falls within the [Windows file-deny bypass advisory](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff). That advisory requires network exposure and does not affect the deployed static build. React Server Components advisories [exclude client-only apps](https://react.dev/blog/2025/12/03/critical-security-vulnerability-in-react-server-components). Current vendor guidance emphasizes [server-side Turnstile validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/) and layered abuse controls. Do not apply generic checklist requirements for passwords, databases, mandatory HSTS preload, or fixed SRI hashes to this app without checking applicability.

Rate limiting and a production test-secret misconfiguration are **not** asserted as live vulnerabilities. The guessed `jm.pages.dev` hostname served unrelated content and was excluded from findings; a Pages project name alone does not establish its deployment hostname.
